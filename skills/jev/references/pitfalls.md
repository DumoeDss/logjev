# LogJev 踩坑与能力边界

## 分布数学

- **温度 0 会破坏读数**：参考默认是 1.0；模型采样文本不用作答案。低温可能让其他标签
  落出 top-k，出现看似精确但丢失信息的结果。
- **重复标签取最大 logprob**：`A` 与 ` A` trim 后相同；最后写入覆盖会让低概率变体替代真值。
- **过滤哨兵**：参考实现丢弃非有限值及 `logprob <= -9000`，不把占位值当作真实候选证据。
- **缺失标签只是近似**：标签不在 top-k 时补 `min(top)-5`；若所有合法标签都缺失，firm
  重读后仍可能落到下限分布。均匀分布不能解释为模型对所有选项都认真评估过。
- **48 项是硬上限，不是推荐规模**：可读取的 top-k 往往更小。候选多时先用规则/检索预筛。
- **score 从 0 开始且可为小数**：三档对应 0/1/2 的加权均值，不是直接返回其中一档文本。
- **noul 不是通用强度量表**：约 0.5 表示是非两可；范围 0.01–0.99，不会达到 0 或 1。
  当前 chat 实现忽略 noul.criteria，重要判断标准写入 instructions。

## 接口与运行

- **401 有两种来源**：客户端错误的桥密钥得到 401；上游拒绝认证在 Node 桥中包装为 502。
  读取诊断，不能对所有错误一概重试。
- **health 不检查上游**：它只反映配置加载与服务在线，不保证密钥、配额或模型功能可用。
- **每题重复上下文**：批量问题按题消耗上游 token，默认 chat 并发 4，排队影响端到端延迟。
- **reads 不统计重试**：当前返回题数；token usage 包含成功返回的重读，失败请求费用也未必
  能从响应完整还原。
- **客户端超时不是取消账单**：fetch abort 停止等待；服务端已经开始的调用可能继续。
- **桥认证与浏览器 demo**：demo 没有 Bearer key 设置框。启用 BRIDGE_API_KEY 后需另用
  支持认证头的客户端；不要因此把上游密钥写进浏览器代码。
- **端点默认值不覆盖用户保存值**：Node `/demos/` 默认连自身；独立 demo 默认连 Python 8012。
  如果看起来连错后端，检查实例 endpoint 和兼容保留的 openjev.* storage。

## 问题设计与应用

- 输出类型正确不代表语义正确。算术、日期、计数、权限和合法动作由代码验证。
- question key 不参与 prompt；不能用 `is_refund` 这个名字补充模糊的 instructions。
- 对开放类别加入 other；对封闭合法动作集按业务设计候选。避免不加区分地强制所有题目用兜底项。
- 候选不是独立评分：增删、重排或修改措辞会影响分布。固定 rubric 并使用自己的数据校准。
- 多问不共享答案，可能出现相互矛盾的判断。用明确一致性规则合成，而非把最高分当作最终许可。
- 阈值附近的抖动需要预设处理方式，不反复调用直到得到期望结果。
- 不可信 state 仍可能注入指令；full 模式的边界提示不等于解决注入问题。后续动作应有独立规则约束。

## 上游和历史数据

README 的兼容性与准确率表来自 Python 版 2026-09 实测，不是 Node 新测结果；Qwen/NIM 行
保留旧温度 0 口径，不能当作当前同条件排名。在线模型、路由、价格变化后要重新验证。

参考探测里 Qwen 的部分 OpenRouter 路由 topk 上限为 5；DeepSeek 直连关闭思考使用
thinking，OR 使用 reasoning。模型名称相同也可能路由到不同后端；缺少 logprobs 的
自动重读只能缓解偶发问题，不能把不支持的模型变成兼容模型。

Python/JavaScript 的任意 JSON 数字格式和数字形式对象键顺序可能不同。严格比较 prompt
字节时，优先使用字符串 state 和具名候选。Golden fixtures 证明覆盖样例的一致性，
不证明所有输入、所有线上 provider 都完全等价。

对接官方 kind: jev 时保持其响应语义；不要把 chat 的 confidence、score、noul 范围或
计费方式硬套到官方输出，也不要依据过去的厂商宣传推断当前性能。
